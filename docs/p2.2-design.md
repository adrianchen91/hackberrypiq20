# P2.2 design: `hw_i2c` (opt-in RP1 hardware I2C on GPIO10/11)

Proposal file: `hackberrypicm5.dts (shipped)`. Default mode is byte-for-byte the P2.1 behaviour (the current `tools/validate-overlay.sh` passes 112/112 on it unchanged).

## Structure

| Frag | Target | Default | `hw_i2c` | Content |
|---|---|---|---|---|
| 0 | `/aliases` | on | off | `i2c11 = "/i2c-gpio"` |
| 1 | `/` | on | off | `i2c-gpio` bus with `touch` (0x48) and `fuel_gauge` (0x36) |
| 2 | `&dpi` | on | on | DPI enable, pinctrl, endpoint |
| 3 | `/` | on | on | `panel` |
| 4 | `&rp1_gpio` | on | on | `hackberry_tp_int` (GPIO27, pull-up) |
| 5 | `/` | on | on | `battery_info` (simple-battery), moved out of fragment 1 so it exists in both modes |
| 6 | `&i2c1` | dormant | on | `status = "okay"`, `pinctrl-0 = <&hackberry_i2c1_10_11 (defined locally)>`, `clock-frequency = <100000>`, `#address-cells`/`#size-cells` (the base node has none), `touch_hw` (0x48), `fuel_gauge_hw` (0x36) |
| 7 | `/aliases` | dormant | on | `i2c11 = "/axi/pcie@1000120000/rp1/i2c@74000"`, `i2c1 = "/hackberry-i2c1-is-i2c11"` |

`hw_i2c = <0>,"!0!1=6=7";`

Each device has two copies, one per bus, with separate labels. Every per-device override lists both labels, so it works in either mode. Overrides that target a label inside a dormant fragment take effect when that fragment is enabled and do nothing otherwise. This was tested with dtmerge, with the param given before or after `hw_i2c`.

## What dtmerge does (tested on this machine, `/usr/local/bin/dtmerge`)

- `+N` / `-N` ignore the value. With `"+6+7-0-1"`, `hw_i2c=off` still switches modes. **Never use them here.**
- `=N` / `!N` honour the value: `hw_i2c`, `=on` and `=1` switch modes; `=off` and `=0` change nothing.
- Fixups in dormant fragments are resolved **even when the fragment stays dormant**. A missing symbol (`hackberry_i2c1_10_11 (defined locally)`, `i2c1`) makes the whole overlay fail in default mode too, which means no DPI and a black screen. All four CM5 base DTBs in `/boot/firmware` (cm5/cm5l × cm5io/cm4io) and the Pi 5 DTBs have both symbols. The proposal passes on all four CM5 bases.
- `"status"` as a boolean is special-cased: `=0` gives `"disabled"`. `"status!"` is not special-cased (`=0` writes an empty `status;`). Never use it.
- Literal assignments (`"status=disabled"`, `"compatible=..."`) ignore the value: `no_touch=off` still disables touch. This is the same as P2.1. Document it as "any value".
- dtc warns `unit_address_vs_reg` on `fragment@6` and `fragment@7`, because it does not recognise `__dormant__` as a fragment. The warning is expected.

## Exclusivity argument (never both controllers on GPIO10/11)

1. The only owners of GPIO10/11 that the overlay can create are `/i2c-gpio` (fragment 1, through `sda-gpios`/`scl-gpios`) and `i2c@74000` with `hackberry_i2c1_10_11 (defined locally)` (fragment 6).
2. Fragments 1 and 6 are switched by the same override token string with opposite operators (`!1`, `=6`). No other override touches fragment state. So for any value of `hw_i2c`, and any number of repetitions, exactly one of the two is merged. Tested: `hw_i2c hw_i2c` gives hw mode, `hw_i2c=on hw_i2c=off` gives gpio mode.
3. In hw mode, `/i2c-gpio` does not exist at all (the fragment is not merged). The node is absent, not merely disabled.
4. In default mode, `i2c@74000` keeps the base `status = "disabled"` and `pinctrl-0 = <&rp1_i2c1_2_3>`.
5. The devices at 0x48 and 0x36 exist exactly once in either mode, because their copies live in fragments 1 and 6, which are mutually exclusive.

Out of scope (base or user config, not this overlay): `dtparam=i2c_arm=on` would enable i2c1 on GPIO2/3, which are DPI pins. It already does that today.

## Bus numbering

- The base `/aliases` has `i2c1 = i2c@74000` and `i2c11 = i2c@70000` (rp1 i2c0, disabled; it also carries `symlink = "i2c-11"`). `of_alias_get_id()` returns the first alias in `/aliases` order that matches the node. Pointing only `i2c11` at `i2c@74000` would therefore still give **i2c-1**.
- Fragment 7 repoints `i2c1` at a path that does not exist. `of_alias_scan()` skips aliases that don't resolve, so `i2c@74000` gets **i2c-11** in both modes (Q1), and Stemma-QT scripts don't change. GPIO2/3 are DPI, so `i2c_arm` (the only use of controller i2c1) can't be used on this board anyway.
- Fallback, if this turns out to bother anything on the device: drop `i2c1 = ...` from fragment 7 and accept i2c-1 in hw mode. Both choices are boot-safe, because aliases do not affect DPI.
- Default mode: `i2c11` moves off rp1 `i2c@70000`. That controller is disabled. If a camera or DSI overlay enables it, it gets a dynamic number (13 or higher), with no collision.

## Pin function

In hw mode, `hackberry_i2c1_10_11 (defined locally)` sets GPIO10/11 to `function = "i2c1"` (12 mA drive, bias pull-up on top of the board's 10 kΩ R34/R35). Nothing requests the pins as GPIOs, because the i2c-gpio node is absent. In default mode, gpiolib takes them as GPIOs in emulated open-drain (RP1 has no native open-drain), and no pinctrl group touches them.

## Validator additions (`tools/validate-overlay.sh`)

The current touch and fuel gauge checks hard-code `^/i2c-gpio/`. Parameterise them by bus path (`BUS=/i2c-gpio` or `/axi/pcie@1000120000/rp1/i2c@74000`), selected per set.

New PARAM_SETS (with `HW_CHECKS = dpi,panel,touch@hw,touch_irq@hw,fuelgauge@hw,gpio27,claims,one_owner,no_i2cgpio,alias_hw,i2c1_hz,unique_devs,monbat@hw`):

- `"hw_i2c_off|hw_i2c=off|${BASE_CHECKS},one_owner,unique_devs"`
- `"hw_i2c_0|hw_i2c=0|${BASE_CHECKS},one_owner,unique_devs"`
- `"hw_i2c|hw_i2c|${HW_CHECKS}"` (also `hw_i2c=on` and `hw_i2c=1`)
- `"hw_i2c_twice|hw_i2c hw_i2c|${HW_CHECKS}"` and `"hw_on_off|hw_i2c=on hw_i2c=off|${BASE_CHECKS},one_owner"`
- hw versions of every existing set: `hw_touch_inv_x`, `hw_touch_inv_y`, `hw_touch_swap_xy`, `hw_no_touch` (`touch_off@hw`), `hw_no_fuelgauge` (`fuel_off@hw`), `hw_fuelgauge_mainline`, `hw_battery_5675`, `hw_pclk_40M`, `hw_i2c_delay_8` (must merge; no delay-us anywhere), `hw_all_flags`
- order sensitivity: `"hw_last|touch_inv_x hw_i2c|${HW_CHECKS},has=touchscreen-inverted-x;"`
- default `default` set additionally: `one_owner,unique_devs` and `nohas=hackberry-i2c1-is-i2c11`

New assertions:

- `one_owner`: the number of enabled nodes that own GPIO10/11 must be exactly 1. Owners are nodes with `*-gpios` on rp1_gpio cells 10 or 11, plus nodes whose `pinctrl-N` resolves (by phandle) to a group containing `"gpio10"` or `"gpio11"`. Expected owner: `/i2c-gpio` in default mode, `i2c@74000` in hw mode.
- `claims` must resolve `pinctrl-N` phandles to their groups' `pins`. The current check only sees literal `"gpioN"` strings in added lines, so a wrong `pinctrl-0 = <&rp1_i2c1_2_3>` (GPIO2/3, DPI) would pass. This is the black-screen case.
- `no_i2cgpio`: there is no `/i2c-gpio` node.
- `alias_hw`: `i2c11 = "/axi/pcie@1000120000/rp1/i2c@74000"` and `i2c1` does not point at `i2c@74000`. In default mode, the existing `alias` check stays.
- `i2c1_hz`: `i2c@74000` has `clock-frequency = <0x186a0>` and `status = "okay"`.
- `unique_devs`: tree-wide, exactly one non-disabled node with `reg = <0x48>` and edt compatible, and exactly one with `reg = <0x36>` and a max17048 compatible.
- `monbat@BUS`: the gauge's `monitored-battery` equals the phandle of `/hackberry-battery`.
- Base matrix: run every set against each `bcm2712-rpi-cm5{,l}-cm{5,4}io.dtb`. Dormant-fragment fixups can break default mode on any base that lacks a symbol.

The harness used for this proposal runs 37 cases, including negative mutants. It caught `+/-` operators (wrong mode for `hw_i2c=off`) and a missing `!1` (two owners, duplicate 0x48/0x36). ## Left for on-device testing (tryboot only)

- `ls -l /sys/bus/i2c/devices/i2c-11` resolves to `i2c@74000` in hw mode and to `/i2c-gpio` in default mode. `11-0048` and `11-0036` are bound, and dmesg shows no `-EBUSY`.
- Touch scribble for 30 s: `top`/`pidstat` CPU for the touch IRQ thread, hw versus gpio mode. Expect lower CPU in hw mode.
- 1 h soak in hw mode: zero `i2c_designware`/`edt_ft5x06`/`max17048` errors. Check designware behaviour with Stemma-QT devices: there is no SMBus quick, so use `i2cdetect -r`.
